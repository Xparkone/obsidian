# RAID 原理、选型与运维指南

## 1. RAID 是什么

RAID（Redundant Array of Independent Disks，独立磁盘冗余阵列）是把多块物理硬盘组合成一个逻辑存储设备的技术，主要目标有三个：

- 提高连续或并发读写性能；
- 提高磁盘故障容忍能力；
- 将多块硬盘的容量组合起来统一使用。

RAID 主要依靠以下机制：

- **条带化（Striping）**：把数据分散到多块盘，提高并行读写能力；
- **镜像（Mirroring）**：保存多份相同数据，提高可靠性；
- **校验（Parity）**：保存校验信息，硬盘损坏后根据剩余数据重建。

> RAID 不是备份。RAID 主要处理硬盘故障，无法防止误删除、勒索软件、程序写坏数据、控制器故障、主机损坏和机房事故。

## 2. 基本概念

### 2.1 条带

假设有两块硬盘，数据被分成多个块并交替写入：

```text
数据块： A1  A2  A3  A4

硬盘1： A1      A3
硬盘2：     A2      A4
```

多块盘可以同时工作，因此吞吐量通常比单盘高。但如果没有镜像或校验，任意一块盘损坏都可能破坏整个阵列。

### 2.2 镜像

同一份数据同时写入两块盘：

```text
          ┌──→ 硬盘1：数据 A
数据 A ───┤
          └──→ 硬盘2：数据 A
```

其中一块盘损坏后，系统仍可通过另一块盘继续提供服务。

### 2.3 校验

校验型 RAID 将数据和校验信息分散在不同硬盘上：

```text
硬盘1        硬盘2        硬盘3
数据 A1      数据 A2      校验 A
数据 B1      校验 B       数据 B2
校验 C       数据 C1      数据 C2
```

一块盘损坏时，可以使用剩余数据和校验信息推算丢失的数据。

### 2.4 阵列状态

- **正常（Optimal/Clean）**：所有成员盘正常；
- **降级（Degraded）**：已有磁盘损坏，但阵列仍可工作；
- **重建（Rebuilding/Resyncing）**：正在把数据恢复到替换盘；
- **失效（Failed）**：损坏数量超过 RAID 的容错能力。

## 3. 常见 RAID 级别

假设硬盘数量为 `N`，最小单盘容量为 `S`。不同容量的硬盘混用时，通常以最小硬盘容量计算。

| RAID | 最少硬盘 | 理论可用容量 | 可容忍故障 | 主要特点 |
|---|---:|---:|---:|---|
| RAID 0 | 2 | `N × S` | 0 块 | 性能高，无冗余 |
| RAID 1 | 2 | 通常为 `S` | 1 块 | 简单可靠，容量利用率低 |
| RAID 5 | 3 | `(N-1) × S` | 1 块 | 容量利用率较高，存在校验写开销 |
| RAID 6 | 4 | `(N-2) × S` | 2 块 | 比 RAID 5 安全，写开销更大 |
| RAID 10 | 4，且为偶数 | `(N/2) × S` | 取决于故障位置 | 性能、恢复速度和可靠性较均衡 |

实际格式化后容量还会受到 TB/TiB 换算、元数据和文件系统预留空间影响。

### 3.1 RAID 0

RAID 0 只进行条带化，不保存镜像和校验。

优点：

- 容量利用率接近 100%；
- 顺序读写和并发性能较好。

缺点：

- 没有任何冗余；
- 任意一块成员盘损坏，整个阵列的数据都可能无法使用。

适用场景：可以随时重新生成的缓存、临时计算数据。不要用于重要业务数据。

### 3.2 RAID 1

RAID 1 将相同数据写入两块或多块盘。

优点：

- 实现简单；
- 单盘损坏后仍可运行；
- 重建通常只需从健康镜像盘复制数据；
- 随机读取可以分散到不同镜像盘。

缺点：

- 两块盘通常只有一块盘的可用容量；
- 误删除和逻辑损坏会立即同步到所有镜像盘。

适用场景：服务器系统盘、重要配置、小型业务存储。

### 3.3 RAID 5

RAID 5 使用一份分布式校验信息，可以容忍一块硬盘损坏。

例如 4 块 4 TB 硬盘：

```text
理论可用容量 = (4 - 1) × 4 TB = 12 TB
```

优点：

- 容量利用率高于镜像；
- 读取性能通常较好。

缺点：

- 小块随机写入需要执行“读取旧数据、读取旧校验、计算新校验、写入数据和校验”，写入延迟较高；
- 降级期间性能下降；
- 大容量机械盘重建时间可能很长；
- 重建期间再损坏一块盘，阵列会失效。

对于大容量机械盘和重要数据，不建议默认选择 RAID 5。

### 3.4 RAID 6

RAID 6 使用两份校验信息，可以同时容忍两块硬盘损坏。

例如 6 块 8 TB 硬盘：

```text
理论可用容量 = (6 - 2) × 8 TB = 32 TB
```

优点：

- 比 RAID 5 多一层磁盘故障保护；
- 更适合大容量机械盘组成的容量型阵列。

缺点：

- 写入校验开销更大；
- 重建期间磁盘负载和延迟明显上升；
- 仍不能替代备份。

适用场景：文件服务器、归档存储、备份服务器等容量优先的场景。

### 3.5 RAID 10

RAID 10 先将磁盘两两镜像，再对镜像组进行条带化：

```text
                 RAID 10
              ┌────┴────┐
           镜像组1     镜像组2
          硬盘1/2      硬盘3/4
```

例如 4 块 4 TB 硬盘：

```text
理论可用容量 = 4 × 4 TB ÷ 2 = 8 TB
```

优点：

- 随机读写性能较好；
- 不需要计算分布式校验；
- 重建通常只需读取对应镜像盘；
- 重建对整个阵列的影响通常小于 RAID 5/6。

缺点：

- 容量利用率约为 50%；
- 同一镜像组的两块盘同时损坏时，阵列会失效；
- “最多能坏几块”取决于损坏的具体位置，不能简单理解为固定数量。

适用场景：数据库、虚拟化平台、高 IOPS 业务存储。

## 4. RAID 实现方式

### 4.1 硬件 RAID

由独立 RAID 控制器负责管理，操作系统通常只看到一个逻辑磁盘。

优点：

- 对操作系统透明；
- 部分控制器具有带断电保护的写缓存；
- 企业服务器管理工具比较完整。

缺点：

- 成本较高；
- 控制器故障后可能依赖同型号或兼容控制器恢复；
- 控制器固件、电池或超级电容也需要监控；
- 如果写缓存没有断电保护，断电可能造成数据损坏。

### 4.2 软件 RAID

由操作系统管理，例如 Linux `mdadm`。

优点：

- 不依赖专用控制器；
- 阵列结构相对透明；
- 成本低，现代 CPU 通常能够承担计算开销。

缺点：

- 使用少量 CPU 和系统 I/O；
- 系统盘 RAID 需要正确配置引导程序；
- 监控、告警和自动巡检需要自行配置。

### 4.3 ZFS

ZFS 把文件系统、卷管理、校验、快照和数据修复结合在一起。

常见布局：

- Mirror：类似 RAID 1；
- RAIDZ1：类似单校验 RAID 5；
- RAIDZ2：类似双校验 RAID 6；
- RAIDZ3：三份校验。

ZFS 可以通过端到端校验发现静默数据损坏，但仍需规划内存、vdev 布局、快照和异地备份。

## 5. RAID 的主要风险

### 5.1 RAID 不是备份

RAID 不能解决以下问题：

- 用户误删除；
- 勒索软件加密；
- 应用写入错误数据；
- 文件系统损坏；
- RAID 控制器或主板故障；
- 整机丢失、供电事故和机房灾害。

完整保护通常包括：

```text
RAID       处理单盘或部分磁盘故障
快照       处理短期误操作和版本回退
备份       处理数据丢失和长期恢复
异地副本   处理整机、机房和地域级故障
```

建议按照 3-2-1 原则设计备份：至少 3 份数据、使用 2 种不同介质、其中 1 份位于异地或隔离环境。

### 5.2 重建风险

更换故障盘后，阵列需要读取健康盘上的大量数据并写入新盘。大容量机械盘的重建可能持续数小时甚至数天。

重建期间：

- 阵列通常处于降级状态；
- 业务延迟会上升；
- 所有成员盘承受持续高负载；
- 老旧磁盘可能在高强度读取中出现新的错误；
- RAID 5 再损坏一块盘就会失效。

发现阵列降级后，应先确认备份可恢复，再更换准确的故障盘。不要只根据 Linux 设备名直接拔盘，应核对序列号、槽位灯和控制器记录。

### 5.3 写空洞（Write Hole）

校验型 RAID 在数据和校验尚未全部落盘时发生断电，可能导致二者不一致。常见防护措施包括：

- 使用带 BBU/超级电容保护缓存的 RAID 控制器；
- 配置 UPS；
- 使用支持日志、校验和崩溃恢复的文件系统；
- 定期执行一致性校验或巡检（scrub/patrol read）。

### 5.4 同批次硬盘风险

同型号、同批次、同时间投入使用的硬盘，可能在相近时间进入故障期。采购和更换时可以适当分散批次，但不要为了批次差异混用性能和容量差异过大的硬盘。

## 6. 选型建议

| 使用场景 | 推荐方案 | 原因 |
|---|---|---|
| 双盘服务器系统盘 | RAID 1 | 配置简单，单盘故障后可以继续启动 |
| 数据库、高 IOPS 业务 | RAID 10 | 随机性能好，重建相对直接 |
| 虚拟化宿主机 | RAID 10 | 更适合多个虚拟机的随机读写 |
| 大容量文件或归档存储 | RAID 6 | 容量利用率和双盘容错较均衡 |
| 临时缓存、可重建数据 | RAID 0 | 性能优先，但必须接受全部丢失 |
| 分布式 MinIO | 独立磁盘/JBOD | 让 MinIO 自身管理纠删码和磁盘故障 |

通用服务器可以参考以下布局：

```text
两块企业级 SSD
└── RAID 1：操作系统、Docker、配置文件

四块数据盘
├── RAID 10：数据库或普通本地业务数据
└── JBOD：分布式 MinIO 等自行管理冗余的软件
```

这只是通用起点，最终选择还要结合容量、IOPS、写入比例、恢复时间目标、预算和备份能力。

## 7. 与 MinIO、SeaweedFS 和 Tempo 的关系

### 7.1 普通单机应用

普通文件系统上的应用可以使用：

```text
物理硬盘 → RAID 1/6/10 → XFS/ext4 → 应用
```

RAID 向应用提供一个逻辑块设备，应用不需要理解底层硬盘布局。

### 7.2 分布式 MinIO

MinIO 本身通过纠删码在多个磁盘或节点之间保存冗余数据。正式的分布式 MinIO 更适合使用独立磁盘：

```text
多块独立磁盘/JBOD
        ↓
MinIO 分布式纠删码
        ↓
跨盘、跨节点的数据保护
```

通常不建议在分布式 MinIO 下再建立一个大型 RAID 5/6，原因包括：

- MinIO 无法直接识别底层单块盘的状态；
- RAID 重建和 MinIO 数据修复可能同时产生大量 I/O；
- RAID 控制器或整个阵列故障会一次性让多个 MinIO 存储路径消失；
- 两层冗余降低容量利用率并增加故障排查难度。

单机测试环境可以在 RAID 1 或 RAID 10 文件系统上运行 MinIO，但它只能提高磁盘层可靠性，不能提供节点级高可用。

### 7.3 SeaweedFS

SeaweedFS 可以通过复制或纠删码实现数据保护。测试使用的单节点 `mini` 模式不具备真正的节点级高可用，即使底层使用 RAID，也仍然存在主机、进程和网络单点故障。

### 7.4 Tempo 对象存储

Tempo 将 Trace 数据块长期保存在对象存储中。生产环境应选择：

- 云厂商对象存储；或
- 跨节点部署的分布式 MinIO；或
- 经过高可用设计的其他 S3 兼容对象存储。

单机 RAID 只能降低硬盘故障风险，不能让 Tempo 的对象存储获得节点级或机房级高可用。

## 8. Linux 软件 RAID 常用检查命令

### 8.1 查看阵列状态

```bash
cat /proc/mdstat
```

详细查看指定阵列：

```bash
mdadm --detail /dev/md0
```

查看块设备、文件系统和挂载关系：

```bash
lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS,MODEL,SERIAL
```

### 8.2 查看硬盘健康状态

安装工具：

```bash
apt-get install -y smartmontools
```

查看 SMART 信息：

```bash
smartctl -a /dev/sda
```

触发短测试：

```bash
smartctl -t short /dev/sda
```

SMART 正常不代表硬盘一定不会故障，应结合 RAID 状态、内核日志、I/O 错误和延迟综合判断。

### 8.3 查看内核磁盘错误

```bash
journalctl -k --since "24 hours ago"
```

重点关注：

```text
I/O error
medium error
UNC
reset
timeout
failed command
```

## 9. 监控与告警

至少监控以下项目：

- RAID 当前状态和降级事件；
- 失败盘、备用盘和缺失盘数量；
- 阵列重建进度；
- SMART 介质错误、待定扇区和不可校正扇区；
- SSD 剩余寿命、磨损比例和温度；
- 磁盘 I/O 延迟、队列长度和吞吐量；
- 文件系统使用率和 inode 使用率；
- RAID 控制器电池、超级电容和缓存状态；
- 内核 I/O error、reset 和 timeout 日志。

可使用以下组件建立监控：

```text
node_exporter          主机、文件系统和磁盘性能指标
smartctl_exporter      SMART 健康指标
厂商 RAID exporter     RAID 控制器和阵列状态
Prometheus             采集与保存指标
Alertmanager           故障告警
Grafana                状态和趋势展示
```

建议对“阵列降级”“磁盘失联”“不可校正错误”“重建失败”设置高优先级告警。磁盘使用率告警可以设置多级阈值，并根据实际增长速度调整。

## 10. 故障处理流程

发现 RAID 降级后，按以下顺序处理：

1. 确认业务影响，减少非必要的高 I/O 操作；
2. 查看 RAID 控制器或 `mdadm` 状态，确认故障类型；
3. 检查最新备份是否存在，并验证关键数据可读取；
4. 记录故障盘序列号、槽位和设备名；
5. 使用容量不小于原盘、性能和接口兼容的新盘进行替换；
6. 观察阵列重建状态、磁盘错误和业务延迟；
7. 重建完成后执行一致性检查，并确认告警恢复；
8. 记录故障时间、硬盘信息、处理过程和恢复结果。

> 不确定故障盘槽位时不要直接拔盘。误拔健康盘可能让已降级的阵列立即失效。

## 11. 上线前检查清单

- [ ] RAID 级别与业务读写模式匹配；
- [ ] 磁盘型号、接口和容量兼容；
- [ ] RAID 控制器固件和驱动已验证；
- [ ] 写缓存具备断电保护，服务器配置 UPS；
- [ ] 已配置热备盘或准备可快速替换的备件；
- [ ] RAID、SMART、温度和 I/O 延迟已经接入监控；
- [ ] 已配置降级和磁盘故障告警；
- [ ] 已建立独立备份和异地副本；
- [ ] 已实际验证备份恢复流程；
- [ ] 已记录硬盘序列号和物理槽位映射；
- [ ] 已制定磁盘更换和阵列重建操作流程。

## 12. 核心结论

- RAID 解决的是部分硬盘故障，不等于备份；
- 系统盘通常选择 RAID 1，高性能业务通常选择 RAID 10；
- 容量型机械盘阵列通常优先考虑 RAID 6，而不是 RAID 5；
- 阵列降级后应先确认备份，再准确定位和更换故障盘；
- 分布式 MinIO 一般使用独立磁盘/JBOD，让 MinIO 自身负责纠删码；
- Tempo 的生产对象存储应具备跨节点高可用，不能只依靠单机 RAID；
- 监控、备件、UPS 和可恢复的备份，与 RAID 级别本身同样重要。
