# 单台服务器巡检指标

## 1. 适用范围

本文用于巡检一台 Linux 服务器本身的运行状态。重点回答：服务器资源是否充足、系统是否稳定、网络是否正常、关键进程是否运行、是否存在需要处理的风险。

中间件、数据库和 Kubernetes 属于服务器上的业务或平台服务，放在本文末尾作为扩展检查，不能代替服务器基础指标检查。

## 2. 一台服务器必须检查的指标

| 类别 | 必查指标 | 需要确认的问题 |
|---|---|---|
| 基础信息 | 主机名、IP、系统版本、内核版本、运行时长、时区 | 当前检查的是否为正确服务器，系统是否发生过异常重启 |
| CPU | 总使用率、user、system、iowait、steal、CPU 核数 | CPU 是否持续繁忙，是否被 I/O 等待或虚拟化争抢拖慢 |
| 内存 | 总量、已用、`available`、swap 使用量、swap in/out | 是否存在内存不足、持续换页或 OOM 风险 |
| 负载 | 1/5/15 分钟 load average | 系统任务是否排队，负载是否超过 CPU 承载能力 |
| 磁盘容量 | `/`、`/data`、日志、容器、数据库等挂载点使用率 | 是否接近容量阈值，是否有快速增长的目录 |
| inode | 各挂载点 inode 使用率 | 是否因小文件过多而无法创建新文件 |
| 磁盘 I/O | 设备利用率、await、读写吞吐、队列、I/O 错误 | 磁盘是否拥塞、延迟过高或出现硬件/文件系统错误 |
| 文件系统 | 挂载状态、只读挂载、异常挂载、NFS 挂载 | 数据盘是否正常挂载，是否出现只读或挂载丢失 |
| 网络接口 | 网卡状态、丢包、错误包、速率 | 网卡是否正常，是否存在链路错误 |
| 网络连通性 | 默认路由、DNS、网关或指定依赖地址可达性 | 服务器是否能访问必要的网络依赖 |
| 端口 | 监听端口、监听地址、对应进程 | 端口是否按预期监听，是否存在异常暴露端口 |
| 进程 | 关键进程、僵尸进程、`D` 状态进程、进程数 | 关键进程是否存在，是否有异常堆积或频繁重启 |
| 系统服务 | 关键 systemd 服务状态、最近重启时间 | 服务是否 active，是否反复失败或被拉起 |
| 系统日志 | OOM、kernel error、I/O error、网络错误、服务失败 | 最近时间窗口内是否出现系统级异常 |
| 时间同步 | 当前时间、时区、NTP/chrony 状态 | 日志、证书、任务调度时间是否可信 |
| 安全与访问 | SSH 失败登录、异常用户/进程、防火墙状态、证书有效期 | 是否存在异常登录、未授权暴露或证书即将过期 |
| 监控与备份 | 监控 Agent、日志采集、备份任务最近一次结果 | 出现故障时是否能发现，数据是否可以恢复 |

## 3. 建议判定标准

阈值是通用起点，应结合服务器规格、业务类型和历史基线调整。

| 指标 | 正常 | 预警 | 告警/紧急 |
|---|---|---|---|
| CPU 使用率 | 持续低于 70% | 持续 70%～85% | 持续超过 85%～90%，并影响响应 |
| CPU iowait | 无明显升高 | 持续升高 | 长时间高位并伴随 I/O 延迟 |
| 内存 `available` | 大于总内存 20% | 低于 20% | 低于 10%、发生 OOM 或关键进程被杀 |
| Swap | 未使用或稳定 | 持续增长 | 持续 swap in/out，业务响应受影响 |
| Load | 低于或接近 CPU 核数 | 长时间接近 CPU 核数 | 持续明显超过 CPU 核数并出现排队 |
| 磁盘容量 | 低于 70% | 70%～80% | 80%～90% 告警，超过 90% 紧急 |
| inode | 低于 70% | 70%～85% | 超过 85%，或无法创建文件 |
| 磁盘 I/O | 延迟稳定、无错误 | 利用率或 await 持续上升 | I/O error、文件系统错误或严重阻塞 |
| 进程 | 关键进程正常 | 有少量异常进程待确认 | 僵尸/`D` 进程堆积或关键进程退出 |
| 网络 | 网卡、路由、DNS 正常 | 偶发丢包或错误 | 持续丢包、接口 down、依赖不可达 |
| 时间同步 | 已同步 | 偏差需要关注 | 未同步或时间明显漂移 |

磁盘阈值应记录具体挂载点。例如“磁盘 80%”不足以定位问题，应写成“`/data` 使用率 80%，主要增长目录为 `/data/logs`”。

## 4. 只读检查命令

以下命令用于采集信息，不执行修改、删除、重启或清理操作：

```bash
# 基础信息、时间和运行时长
hostnamectl
hostname -I
uname -a
uptime
timedatectl

# CPU、内存、负载和进程
nproc
lscpu | sed -n '1,25p'
free -h
vmstat 1 5
ps -eo pid,ppid,stat,comm,%cpu,%mem --sort=-%cpu | head -30

# 磁盘、inode、挂载和空间增长线索
df -hP
df -ihP
findmnt
lsblk -f

# 磁盘 I/O（已安装 sysstat 时）
iostat -xz 1 3

# 网络接口、路由、连接和监听端口
ip -br addr
ip -s link
ip route
ss -s
ss -lntup

# 系统服务和最近日志
systemctl --failed --no-pager
systemctl is-active <service>
systemctl --no-pager --full status <service>
journalctl --since '1 hour ago' --priority=warning --no-pager
journalctl -k --since '1 hour ago' --no-pager

# 时间同步（按实际组件选择）
timedatectl show-timesync --all
chronyc tracking

# Kubernetes 节点上再执行
kubectl get nodes -o wide
kubectl describe node <node-name>
```

命令输出中不得记录密码、Token、Cookie、私钥或完整认证头。`ss -lntup`、日志和进程输出应按需要脱敏。

## 5. 巡检顺序

1. 核对主机名、IP、时间和巡检时间窗口；
2. 检查 CPU、内存、负载和进程；
3. 检查容量、inode、挂载和 I/O；
4. 检查网卡、路由、DNS、监听端口和依赖连通性；
5. 检查 systemd、内核和系统日志；
6. 检查时间同步、监控 Agent、备份任务和安全异常；
7. 如果服务器承载业务，再执行对应服务的健康检查；
8. 对异常保留原始证据、时间点、影响范围和责任对象。

## 6. 承载业务时的扩展检查

如果这台服务器运行数据库、中间件、对象存储或镜像仓库，还需要按服务补充：

- 进程、端口和 systemd/容器状态；
- 服务健康接口或客户端最小只读检查；
- 连接失败、错误日志和最近重启记录；
- 数据目录和日志目录容量增长；
- 主从、复制、集群成员、副本或分片状态；
- 证书有效期和认证异常。

端口处于 `LISTEN` 只能证明 socket 已监听，不能证明服务能够完成认证、读写或业务请求。
